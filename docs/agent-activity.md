# Personal agent activity

`GET /api/agent-activity` and MCP `agent_activity` read the signed-in account's recent connections and successful content edits. They include all of that account's personal tokens, including recently used revoked tokens. They do not expose anyone else's credentials or activity, and they do not change their own activity or usage summary.

`tokenID` filters by a stable nonsecret token ID. `limit` defaults to 50 and accepts 1–100. Pass `nextCursor` back as `cursor` with the same token filter for the next page. Items are ordered by occurrence time and event ID, newest first. History expires after 30 days and holds at most 1,000 events per account. Repeated MCP initialization within one minute for the same token and client produces one connection row.

Each item names the token label at the time, transport, optional self-reported client/version, occurrence time and operation. A token's name is display text, never identity or evidence of client software. Revocation immediately prevents new authenticated requests; retained history uses its independent token ID and contains no secret or credential hash. Historical labels do not change if token names change. Titles and URLs are resolved against current artifact access, never stored in this history. Deleted or inaccessible targets have no target object, ID, title or URL. Links open the current artifact; this API offers no historical-version link.

Client names and versions are self-reported and are not proof of a process or person. Nonempty names from any client are accepted; known client prefixes keep their canonical display labels. Names are trimmed, control characters removed and limited to 60 Unicode characters; versions are limited to 40. The same bounded display name is used for activity, room presence and version attribution, without granting authority. MCP is stateless. A request that supplies no client identity stays unknown even if another client sharing the token identified itself earlier. Unknown clients are shown without a version. HTTP API use has unknown client identity. Neither token labels, user-agent headers nor artifact authors are used to guess the client. Last connected means successful explicit MCP initialization; a stateless client can use tools without initializing and therefore have last used without last connected. Last used records successful API/tool use, throttled to one minute. Cookie browser activity, signed file grants and staging uploads are not agent connections.

Content activity covers create/update/publish, completed large publishes, restore, `doc_edit`, `board_edit`, and Design frame publishes. Each changed live edit is recorded with its durable update before a quiet snapshot. Failed, stale, invalid and unchanged mutations, staging uploads and protective/background snapshots create no edit rows. Repeated persistence for one logical operation uses one event ID. An activity storage failure rejects the same transaction as its version or live-log update; it never reports a committed write as rolled back due to a later history write. Protocol/use-summary recording failures are logged without replacing the operation result.

No headers, request bodies, artifact content, prompts, file paths, IP addresses, token secrets or token hashes are collected in this history. It is personal connection/edit metadata, not an organisation audit log or read-by-read browsing history. Existing version history and room presence remain separate features.
