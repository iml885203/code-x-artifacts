# internal/designroom

design 在 room 裡（`docs/design-room.md`）：扁平節點樹、frame 與樹的互轉（逐 byte 相同）、`Move`／`SetStyle`／`EditText`／`Delete`、環的檢查。純函式加 ygo，不 log。`interop/` 是用真的 yjs 寫、讀格式化文字 fixture 的 Node 腳本（自己的 go.mod）。

## 不變式

- **manifest 與每個 frame 是一個共享 `Y.Map` 裡的扁平節點樹（`parent`、`order` 小數索引、編輯器擁有的 style 屬性各一個 entry、其餘屬性與宣告放在 `attrs`／`rest`、文字是 `Y.Text`），寫回的 frame 檔案與進去時逐 byte 相同；版本是 room 序列化出的檔案。**
  搬動只寫 `parent` 與 `order`，所以搬動與改字互不影響；兩個人改同一元素的不同 style 屬性都留著（編輯器擁有的屬性是 `properties.go` 的清單，與 `web/src/design/properties/owned.json` 相同，`display` 除外：它有 `display:flex` 與標記自己的 `display:none` 兩種用法，不能有 slot；屬性面板寫的每個屬性在存下的檔案裡只有那一個宣告不同），同一個屬性只有一個贏而且兩邊一致；**每個 style entry 與 `hidden` entry 的值都由 `Check`（與 `SetStyle`）依 `values.go` 的文法驗證，不合格的更新被 hub 拒絕、不存、不廣播（不能結束宣告或規則、不能載入位址、只收編輯器擁有的屬性）**；會形成環的搬動被拒絕且樹不變（`ErrCycle`）。
  刪除（`Delete`）拿掉元素與裡面每個節點的每個 entry，body 不能刪；別人同時對被刪節點寫的 style entry 沒有 kind，讀取時忽略，frame 照樣可讀。瀏覽器的編輯器（`web/src/design/edits.ts`、outline 的 `tree.ts`）直接寫 room 的 map，key 的拼法與這裡相同；改名是元素 `attrs` 裡的 `data-name`、隱藏是元素自己的 `hidden` entry（`1`／`0`，不覆蓋 `s|display`，所以顯示時屬性面板寫的 display 回來），兩者存下的檔案與前一版只差那一處；移動後存下的檔案與移動前只有被改的宣告不同（前後整份比對）。

- **頁面與 frame 的結構是每個值一個 entry（`s|page|`、`s|row|`、`s|frame|`，位置是小數索引），`design.json` 是它們的投影，所以同時結構化的人互相合併而不是互相覆蓋：兩個人各新增 frame、一個改名一個調整大小、各搬不同的 frame 都留著；一個刪頁面另一個正在搬裡面的 frame，兩邊得到相同的設計、沒有被拒絕。`Check` 只拒絕一個人的寫入能做錯的值（邊長要 1 到 8192、名稱非空且至多 80 字、id 與檔名），訊息點名限制；合法動作加起來的結果（頁面超過 20、頁面的 frame 都被刪光）由投影略過、存成版本時才驗證。**
  瀏覽器寫的空 frame（`web/src/design/pages/structure.ts` 的 `emptyFrameEntries`）與這裡讀回來的是同一個空 frame；刪掉頁面的 frame entries 之後版本沒有那些檔案，掛在已刪的列或頁面上的 frame 不屬於設計；`Room.Frame` 讓 server 在版本存下之前就能畫房間裡新增的 frame；只有舊的單一 `manifest` entry 的房間照舊讀、照整份規則檢查。Go 寫的結構與 yjs 寫的都讀得懂，兩個 yjs client 同時改的合併 Go 讀到全部。

- **內容是文字加行內標記的元素，在 room 裡是一個 `Y.Text`（`rich` entry：字是文字、`<br>` 與不編輯的標記是 embed、被編輯的行內元素 `b strong i em u a span code` 是 `f:<pid>` 的 format），寫回的 HTML 與進去時逐 byte 相同；兩個人改同一元素的不同字都留著；有版面的行內元素（定位、尺寸、`display`）不是文字，它所在的元素維持樹的節點；每個人寫進 room 的格式化文字都受發佈同一份規則限制，不合格的更新被 hub 拒絕；`https:` 與 `mailto:` 的 `<a href>` 讀回來時是 `target="_blank"`、`rel="noopener noreferrer"`，與發佈的連結相同。**
  純文字的元素維持一個文字節點（編輯器今天寫的），行內元素與 embed 裡的 `data-pid` 不是樹的節點。編碼（format 的值是 JSON 字串 `{"t","d","a"}`、embed 是 `{"br"}` 或 `{"raw"}`）由 `testdata/cases` 定義，Go 與真的 yjs 兩個方向都讀得懂：`testdata/go` 是 Go 寫的、`testdata/yjs` 是 yjs 產生的，`make verify-interop` 檢查。
