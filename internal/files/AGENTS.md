# internal/files

版本檔案（script、樣式、資料）的規則：路徑、型別、內容檢查、發佈差異怎麼套用、限制。純函式，不碰磁碟與資料庫（位元組在 `internal/assets` 的 `Disk`，manifest 在 `internal/store`）。

## 不變式

- **一個版本 = 進入頁面 + 一組相對路徑的檔案（`html`、`react` 與 `design` 收；`doc`、`slides` 收到 `files` 以「takes no files」拒絕，不是忽略），兩者在同一個 transaction 存下、永不覆寫；舊版本的檔案隨版本留著，還原是新版本、帶回那一版的檔案。** 發佈的 `files` 是 `{路徑: 文字 | null}`，套用在最新版的檔案組上：寫到的新增或取代、`null` 移除（沒有這個檔案就拒絕並列出現有的）、沒寫到的帶過去；有 `files` 的版本在 base 以外的版本之後存會被拒絕（`FilesFrom`，沒有 `baseVersion` 也一樣）。規則：只收 `.html`、`.js`、`.mjs`、`.css`、`.json`，內容是 UTF-8、無 NUL、`.json` 能 parse；路徑相對、最多 5 層與 200 字元、每段只含 `A-Za-z0-9._-` 且不以 `.` 開頭、不含 `..`、只差大小寫視為衝突、不能是 `index.html`；拒絕而不改寫。限制是 16 MB 一個檔、一次 255 個、一個版本 511 個與 256 MB，帶 `files` 的請求本體 64 MB（沒帶的 10 MB），訊息說出是哪個限制。位元組存在資料卷的 `{assets dir}/{artifact id}/blobs/{sha256}`（內容定址、寫入冪等），manifest 是 SQLite 的 `version_files`，與版本列同一個 transaction；發佈先寫 blob 再開 transaction，失敗只留下沒被引用的 blob，由 `Server.Maintain` 在啟動時與每天掃描、刪掉超過一天的；缺的 blob 是 500 與 log，不是空檔。HTTP 與 MCP 同一個 `Service.Create`/`Update`；`export/html` 對有檔案的版本拒絕（下載會是壞頁面）。
