# internal/roomkind

Design working documents have an 8 MiB encoded-log budget; generic documents keep 2 MiB. Seed, load and updates share the bound. Oversized retained logs are refused without rewriting or reseeding; a compatible capacity can reopen the same history. Tests: `TestDesignSeedsAndLoadedRoomsUseTheSameBoundWithoutDestroyingAnOversizedLog`, `TestDesignCapacityIsSeparateFromTheGenericDocumentLimit`.

room 與版本之間（`docs/doc-room.md`）：`Codec`（一種內容怎麼進出 room）、`SeededLog`、`Snapshotter`。不知道 socket，也不知道內容的意思（交給 codec）。

## 不變式

- **版本從 room 來，只有自動的兩種：room 安靜 2 分鐘後，以及還原之前的保護版本；沒有「現在儲存」，版本從不被覆寫或間引。** 版本的作者是這段期間編輯過的、被認證的身分（連線被授權的帳號或 `Hub.Edit` 的呼叫者），不是 awareness 自報的名稱；和上一版相同的快照不寫（`Version.authors` 列出全部作者，`author` 是第一位）。待存的編輯不會遺失：它們在 update log 裡，等待記錄在 store（`rt_pending`），最後一個編輯者離開或 server 重啟之後，room 下一次安靜就成為版本。還原在 room 有 log 時是寫進 room（在場的人即時看到），之後存一個還原的版本，舊版本不動；room 裡未存的內容先成為保護版本。從 room 切出的內容經過和發佈同一套驗證，doc 不該有的內容（`javascript:` 連結）不會成為版本。

- **doc 的 room 有 log（開過）時，整份 `publish` 與還原都先寫進 room，版本的內容就是 room 的內容；沒開過的 doc 照舊直接存版本。** 寫進 room 只改不同的地方（`docroom.Content.Apply`）：沒變的區塊不動、id 保留，別人正在打的字留著，在場的人即時看到。room 裡有還沒存成版本的內容時先存成保護版本；帶 `baseVersion` 的 publish 因此以過期處理（Conflict 附最新版），不帶的在其上取代。存不了的 room（內容 doc 不能有）重試的間隔每次加倍、只記一次 error。

- **design 的 `roomkind.Codec` 內容是 `kind.Bundle`（內容加檔案）；`Service.SaveFromRoom` 把 room 的檔案以差異存進版本。**
  Tests: `TestADesignsRoomStartsFromTheFramesOfItsLatestVersion`, `TestAVersionFromADesignsRoomIsTheFramesTheRoomSerialisesAndOnlyAfterThePause`, `TestRestoringADesignVersionWritesItsFramesIntoTheRoomAfterAProtectiveVersion`, `TestACycleMadeOfTwoPeoplesMovesIsRefusedByTheHubAndTheRoomKeepsWhatItHad`
- **room 開著時，對 design 的 `publish`（帶 `files`）是合併進 room 的變更，不是旁邊多一個版本：room 的內容只經 room 寫（`Merger.Merge` → `designroom.Merge`），agent 沒改的地方（別人同時改的別的屬性、別的元素、別的字）留著；版本是 room 安靜之後的快照，agent 在製作者之中。過期的 `baseVersion` 照舊以 Conflict 拒絕並附最新版；與別人同時改同一處、或編輯器不收的值以訊息拒絕，room 不變。agent 在 room 裡以名字與它改的元素出現，閒置後消失；`read` 的 `file` 讀到的是 room 現在的樣子，也是 agent 下一次發佈所建立在的樣子（`ReadSource`、`ReadSourceFile` 回傳逐檔 `sourceBases`，發佈時明確帶回；沒有 proof 不推測 saved baseline）。**

- Source snapshots read the complete bundle and epoch under one Hub read lock; reading one file (`SourceFile`: the live frame address and file reads over HTTP and MCP) reads that file, design.json and the epoch under one Hub read lock and builds no other file, because a canvas asks for every frame at once. Explicit read bases remain independent across later reads; a stale overlapping edit still conflicts. Quiet snapshots remain admission-free because they change neither ACL nor live source.
