# internal/designfmt

design 的格式（`docs/design-format.md`）：`design.json` 的解析與驗證、frame 的標籤／屬性／位址／CSS 規則、正規形式與 `data-pid`、review。純函式，不 log。

## 不變式

- **`design.json`（`version`、`pages`、每頁的 `rows` 與 frame 的 `id`、`name`、`file`、`w`、`h`）加每個 frame 一個 `frames/<名稱>.html`；不合格的設計以每個問題一行、以位置開頭的訊息整份拒絕，什麼都不存，HTTP 與 MCP 的結果與拒絕相同。** `Validate` 是規則層：manifest 的欄位、範圍與唯一性（重複的 frame id、共用的檔案、`w`／`h` 超過 8192）、每個 frame 的檔案都在、標籤與屬性的 allow-list（沒有 script、事件屬性、外部位址）、CSS 的屬性 allow-list 與 at-rule；`design.json` ≤ 256 KB、一個 frame ≤ 512 KB、≤ 60 個 frame、≤ 20 頁。發佈時每個送來的 frame 存正規形式（解析、寫回一次、標準模式、`<body>` 以下每個元素一個 `data-pid`，已有的保留），冪等，且不改任何屬性、style 宣告或 CSS 的位元組；存下來與送來不同的檔案以 `rewritten` 回給 agent；frame 的 review 放在 `review`（缺 alt、超出邊緣、估計放不進框的文字、沒有瀏覽器會套用的屬性、沒有文字；只讀 inline style、只說 likely，不拒絕發佈）；allow-list 的寬度由真實 agent 頁面量測，依據寫在 `docs/design-format.md`；行內文字（`b strong i em u a span code` 被編輯、`mark small …` 原樣保留、有版面的 `span` 不算文字）的定義在 `inline.go`，發佈與 room 共用；`<a href>` 可以是 `https:` 或 `mailto:`（其他標籤與屬性的外部位址仍拒絕），`Normalize` 讓它 `target="_blank"`、`rel="noopener noreferrer"`（Logan 的決定；room 讀格式化文字時用同一個 `OpenLinkInANewTab`）；超過 512 KB 的拒絕訊息教人用 `upload_asset` 並指出最大的 `data:` 位址；guide 的每個範例都通過 `Validate`。
